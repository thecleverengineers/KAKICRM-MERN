# Deploy KAKI CRM through `https://www.kakicrm.store`

This production deployment keeps MongoDB, `.env`, uploads and PM2 data intact.
The Node process stays private on `127.0.0.1:4000`; Nginx serves the public
HTTPS domain and forwards web, API and Socket.IO traffic safely to it.

## One-time domain prerequisites

1. Point both DNS records to the production server:

   - `kakicrm.store` → server public IP
   - `www.kakicrm.store` → server public IP

2. In aaPanel, create the website for `kakicrm.store`, add
   `www.kakicrm.store` as a domain/alias, then issue one Let’s Encrypt
   certificate covering **both** names. Do this before running the command
   below; the script intentionally refuses to create an HTTPS virtual host
   without a certificate.

## Update an existing installation

1. Upload the release ZIP as `/root/KAKI_CRM_PM2_Invoice_Items_Edit_Delete_Update.zip`.
2. Run this as `root`:

```bash
set -Eeuo pipefail

APP_DIR=/www/kaki
APP_PORT=4000
APP_NAME=kaki-crm
APP_DOMAIN=www.kakicrm.store
APP_APEX_DOMAIN=kakicrm.store
APP_ORIGIN="https://${APP_DOMAIN},https://${APP_APEX_DOMAIN}"
UPDATE_ZIP=/root/KAKI_CRM_PM2_Invoice_Items_Edit_Delete_Update.zip
STAGE_DIR="$(mktemp -d /tmp/kaki-crm-domain-update.XXXXXX)"
trap 'rm -rf "$STAGE_DIR"' EXIT

test -d "$APP_DIR"
test -f "$APP_DIR/.env"
test -f "$UPDATE_ZIP"

unzip -q "$UPDATE_ZIP" -d "$STAGE_DIR"
test -f "$STAGE_DIR/kaki-crm-modern/package.json"

# The release contains no .env, MongoDB data, uploads, node_modules or dist.
cp -a "$STAGE_DIR/kaki-crm-modern/." "$APP_DIR/"

cd "$APP_DIR"
APP_DIR="$APP_DIR" APP_PORT="$APP_PORT" APP_HOST=127.0.0.1 \
APP_ORIGIN="$APP_ORIGIN" PM2_APP_NAME="$APP_NAME" bash update-production-pm2.sh

# Detects aaPanel or standard Nginx, backs up the current vhost, validates it,
# reloads Nginx and verifies the HTTPS domain locally.
APP_DIR="$APP_DIR" APP_PORT="$APP_PORT" APP_DOMAIN="$APP_DOMAIN" \
APP_APEX_DOMAIN="$APP_APEX_DOMAIN" APP_ORIGIN="$APP_ORIGIN" \
PM2_APP_NAME="$APP_NAME" bash configure-domain-nginx.sh

pm2 status "$APP_NAME"
curl --fail --silent --show-error --resolve "${APP_DOMAIN}:443:127.0.0.1" \
  "https://${APP_DOMAIN}/api/health"
printf '\nOpen: https://%s/\n' "$APP_DOMAIN"
```

Afterward, use `https://www.kakicrm.store/` only. Port `4000` is the private
local application port for Nginx and PM2 health checks, not the public CRM URL.

## If Nginx shows `403 Forbidden`

That page is generated by the existing aaPanel website virtual host, before the
request reaches KAKI CRM or PM2. Re-run the domain proxy command against the
active root-domain vhost. It makes a timestamped backup before replacing it:

```bash
set -Eeuo pipefail

APP_DIR=/www/kaki
APP_PORT=4000
APP_NAME=kaki-crm
SITE_CONF=/www/server/panel/vhost/nginx/kakicrm.store.conf

test -f "$SITE_CONF" || {
  find /www/server/panel/vhost/nginx -maxdepth 1 -type f -name '*kakicrm*.conf' -print
  exit 1
}

cd "$APP_DIR"
APP_DIR="$APP_DIR" APP_PORT="$APP_PORT" APP_DOMAIN=www.kakicrm.store \
APP_APEX_DOMAIN=kakicrm.store \
APP_ORIGIN=https://www.kakicrm.store,https://kakicrm.store \
PM2_APP_NAME="$APP_NAME" NGINX_CONF="$SITE_CONF" \
bash configure-domain-nginx.sh
```

If the command says that it cannot find a certificate, issue/reissue a single
aaPanel Let’s Encrypt certificate for both `kakicrm.store` and
`www.kakicrm.store`, then run the same command again.

For a first installation, install the application first and then run the
domain command above:

```bash
cd /www/kaki
APP_DIR=/www/kaki APP_PORT=4000 \
APP_ORIGIN=https://www.kakicrm.store,https://kakicrm.store \
MONGO_MODE=existing EXISTING_MONGO_PORT=27017 bash install-production-pm2.sh
```

The installer supports Node.js 24 and MongoDB 8. The domain proxy supports the
responsive mobile app bar, live Socket.IO notifications and the dashboard
shift controls without exposing the Node port publicly. On mobile devices, the
bottom app bar shows permission-aware Home, Tasks, Shift, Alerts and More
shortcuts.
